# Деплой Nova AI на Timeweb Cloud

Схема как у WorkKit: один VPS с Docker, Caddy впереди всего стека сам выпускает HTTPS-сертификат.

```
Интернет ─► Caddy :80/:443 (HTTPS, редирект www → 24nova-ai.ru)
              └─► web (nginx: сайт + /api) ─► api (FastAPI) ─► Postgres + pgvector, Redis
```

Наружу открыты только порты 80 и 443. База, Redis и API доступны только внутри Docker-сети.

## 1. Сервер

1. Timeweb Cloud → «Облачные серверы» → создать: **Ubuntu 24.04**, в маркетплейсе образ **Docker**, от 2 vCPU / 4 ГБ RAM / 40 ГБ NVMe.
2. Добавьте свой SSH-ключ. Запомните IP сервера.
3. Если создали без образа Docker:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
4. Файрвол (если включён): разрешить входящие TCP 22, 80, 443 и UDP 443.

## 2. Домен 24nova-ai.ru

В Timeweb → «Домены и SSL» → `24nova-ai.ru` → DNS:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP сервера |
| A | `www` | IP сервера |

Проверка: `dig +short 24nova-ai.ru` возвращает IP сервера. Без этого Caddy не сможет выпустить сертификат.

## 3. Почта support@24nova-ai.ru

1. Timeweb → «Почта» → подключить домен `24nova-ai.ru` → создать ящик **support@24nova-ai.ru** и задать ему пароль.
2. Если DNS домена в Timeweb, записи MX, SPF и DKIM панель добавит сама. Иначе возьмите их в разделе почты и добавьте вручную:
   - `MX` → `mx1.timeweb.ru`, `mx2.timeweb.ru`
   - `TXT @` → `v=spf1 include:_spf.timeweb.ru ~all`
   - `TXT` DKIM — значение из панели почты
   - рекомендуется `TXT _dmarc` → `v=DMARC1; p=none; rua=mailto:support@24nova-ai.ru`
3. В `.env` на сервере:
   ```env
   SMTP_HOST=smtp.timeweb.ru
   SMTP_PORT=465
   SMTP_SECURITY=ssl
   SMTP_USER=support@24nova-ai.ru
   SMTP_PASSWORD=пароль_ящика
   ```

На этот адрес приходят обращения из личного кабинета: «Ответить» в почтовом клиенте отвечает пользователю напрямую. Отсюда же уходят письма восстановления пароля и ответы поддержки из админки.

> Если письма не уходят (в `./scripts/logs.sh api` видна ошибка соединения), уточните в поддержке Timeweb, не закрыт ли на сервере исходящий порт 465.

## 4. Первый запуск (чистый сервер)

```bash
ssh root@IP_СЕРВЕРА
git clone <URL_РЕПОЗИТОРИЯ> /opt/nova
cd /opt/nova
./scripts/bootstrap.sh
```

`bootstrap.sh` делает всё сам, и его можно запускать повторно:

1. Ставит Docker, если его нет. При RAM < 3,5 ГБ добавляет swap 2 ГБ для сборки фронтенда.
2. Открывает в ufw порты 22, 80 и 443.
3. Создаёт `.env` со случайными паролями и спрашивает ключи. Секреты при вводе не видны, Enter — пропустить.
4. Проверяет, что A-запись `24nova-ai.ru` указывает на этот сервер.
5. Выполняет `docker compose up -d --build` и ждёт готовности. Миграции и стартовые данные применяются автоматически.
6. Ждёт HTTPS-сертификат и прогоняет `smoke.sh https://24nova-ai.ru`.

В конце печатает ссылку на сайт, логин и пароль админа и список того, что ещё не настроено.

Если DNS ещё не обновился, сайт всё равно запустится, а Caddy сам получит сертификат, как только запись начнёт указывать на сервер.

Альтернатива без git — загрузить код с компьютера: `./scripts/deploy.sh root@IP_СЕРВЕРА`.

Вход в админку: https://24nova-ai.ru/login. Пароль покажет `bootstrap.sh`. Смените его в «Профиле».

### Что сервис не пустит в продакшен

API не стартует и пишет причину в лог, если:
- осталась `COOKIE_SECURE=false` или `PUBLIC_URL` не на `https://`;
- пароль администратора дефолтный или короче 12 символов;
- не задан `POSTGRES_PASSWORD`.

Работает, но с предупреждением в логе:

| Чего нет | Что происходит |
|---|---|
| `OPENAI_API_KEY` | Чат отвечает «модель недоступна», искры не списываются |
| ЮKassa | Пополнение закрыто, на странице баланса баннер «напишите на support@» |
| SMTP | Письма не отправляются |

Тестовая оплата `PAYMENT_PROVIDER=mock` в продакшене всегда выключена.

## 5. ЮKassa

1. В личном кабинете ЮKassa: магазин → настройки → HTTP-уведомления → URL `https://24nova-ai.ru/api/v1/billing/webhook/yookassa`, событие `payment.succeeded` (и `payment.canceled`).
2. В `.env` впишите `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, затем `docker compose up -d`.
3. Перед подключением заполните реквизиты в юридических страницах: `frontend/src/pages/Legal.tsx`, константы `OPERATOR` и `REQUISITES`. Платёжная система проверяет оферту.

## 6. Обновления

```bash
cd /opt/nova && ./scripts/update.sh
```

Скрипт делает бэкап, затем `git pull`, пересборку и смоук-тест. Миграции применяются автоматически, данные в томах сохраняются.

**Никогда не выполняйте `docker compose down -v`** — это удалит базу.

## 7. Бэкапы (автоматически)

Сервис `backup` работает внутри Docker Compose, cron не нужен:

- **Расписание и хранение.** Дамп делается каждый день в `BACKUP_TIME` (по умолчанию 04:00 МСК) и при первом старте. Дампы старше `BACKUP_KEEP_DAYS` (14 дней) удаляются.
- **Проверка.** Каждый дамп проверяется (`pg_restore --list`) и только после этого считается успешным.
- **Мониторинг.** Если бэкапа нет больше 26 часов, `docker compose ps` покажет `backup` как `unhealthy`. В админке на вкладке «Обзор» карточка станет красной.
- **Где лежат.** Дампы хранятся в `/opt/nova/backups/` на сервере.

**Копия вне сервера (рекомендуется).** Timeweb Cloud → «Хранилище S3» → создайте приватный бакет (например `nova-backups`) и ключ доступа, затем в `.env`:

```env
S3_BUCKET=nova-backups
S3_ENDPOINT=https://s3.twcstorage.ru   # проверьте адрес в панели хранилища
S3_ACCESS_KEY=...
S3_SECRET_KEY=...
```

Затем `docker compose up -d backup`. Каждый дамп будет копироваться в бакет, старые копии удаляются там же. Если S3 недоступен, локальный бэкап всё равно делается, а в админке появится «S3: ошибка».

**Команды:**

```bash
./scripts/backup.sh                          # бэкап прямо сейчас
./scripts/verify-backup.sh                   # развернуть свежий дамп во временную БД и сверить данные
./scripts/restore.sh backups/nova-….dump     # восстановить (спросит подтверждение)
```

## 8. Полезное

```bash
docker compose ps                         # состояние сервисов
./scripts/logs.sh api                     # логи API (ошибки моделей, почты, оплаты)
./scripts/logs.sh caddy                   # выпуск сертификатов, входящие запросы
docker compose exec api alembic current   # версия схемы БД
docker compose exec db psql -U nova nova  # консоль базы
```
